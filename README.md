日出日落有约 1 分钟量级的系统性偏差，来自折射修正与第三方采用的日出判据略有差异（是否计入观测者海拔、采用哪种折射常数）。**高度角和方位角是精确的** —— 它们是纯几何量，没有折射约定问题。

`verify.mjs` 里还有 **32 条断言**，覆盖的不只是"和参考值对得上"：

- 赤道全年昼长恒为 **12 小时 07 分**（比 12 小时略长，因为折射让日面提前升起、延后落下）
- 南北半球季节相反（悉尼 12 月 21 日是全年最长的一天，约 14h25m）
- 太阳正午必须**正南**（北半球中低纬）或**正北**（南半球），误差 < 0.03°
- 90°N / 90°S 的极昼极夜不产生 `NaN`
- 高度角在一天内的连续性（方位角每分钟的变化步长有上界）

```
$ node verify.mjs
```

## 顺手发现的几件事

写的过程中被数据纠正或惊讶到的，记在这里：

- **上海的正午不在 12:00，在 11:40。** 这 20 分钟由两部分组成：均时差 +14 分（10 月中旬太阳"跑快了"），加上上海在 121.47°E、比东八区中央经线 120°E 偏东 1.47°（≈6 分钟）。
- **赤道的白昼不是 12 小时整，是 12 小时 07 分。** 因为大气折射让日面提前升起、延后落下。基多全年的昼长只差 1 分多钟 —— 在那里，季节几乎不存在。
- **上海全年昼长要摆动约 4 小时**（14h10m ↔ 10h06m）。而且**变化最快的时候不在夏至前后，而在分点附近**：10 月 14 日一天就短掉 1 分 50 秒，到了 12 月反而趋于停顿。
- **方位角从正北顺时针数**，所以 261° 落在"南与西之间" —— 太阳是"正西偏**南**"落下的，不是偏北。我第一版把南北写反了，靠这个几何关系抓出来。
- **纬度越高，"下一个转折点"来得越晚。** 特罗姆瑟在夏至之后还要 34 天才开始变短。

## 快速开始

不需要任何依赖、构建或安装：

```bash
git clone https://github.com/RintoTan/sol-sun-path.git
cd sol-sun-path
open index.html          # macOS；Windows 用 start，Linux 用 xdg-open
```

想要本地起个服务（比如为了在手机上开）：

```bash
python3 -m http.server 8000
# 然后访问 http://localhost:8000
```

跑数值测试需要 Node.js：

```bash
node verify.mjs
```

### 部署

仓库本身就是 GitHub Pages 站点：`index.html` 在根目录，Pages 源设为 `main` 分支 `/`。改完 `index.html` 推上去，等约 30 秒构建完成即可。

## 工程笔记：踩过的坑

单文件、零依赖意味着没有构建工具替你兜底。下面这些全是真撞出来的，留个记录：

1. **`svg.innerHTML = ''` 会把紧挨着写在 `<svg>` 里的 `<defs>` 一起清掉。** 渐变和滤镜随即引用不到，元素在 Chrome 里**不是变透明，而是根本不画**。修法：把 `<defs>` 放在被清空的图层容器之外，只清动态内容。
2. **跨 `<svg>` 引用 `url(#id)` 不可靠。** 无论渐变（`fill` 引用）还是滤镜（CSS `filter` 引用），只要定义在另一个 `<svg>` 里就可能失效。修法：每个 SVG 自带一份 `<defs>`。
3. **一个静默的单位错误让整页蒙上了一层暖色。** 昼长换算函数 `sy()` 收的是"小时"，我传了"分钟" —— 689 分钟被当成 689 小时，曲线被画到页面上方 4000 多像素之外；又因为 SVG 是 `overflow: visible`，它溢出成了一层盖住整页的暖色蒙版，看起来像"配色出了问题"。最后靠**解码截图采样真实像素** + `document.elementsFromPoint()` 拿到该点的完整元素栈，逐层剥离才定位到。
4. **极昼时"截取地平线以上弧段"的函数返回了对象而不是坐标对**，导致 `toPath()` 抛异常、整个 `render()` 中断。症状很阴险：**读数面板是新的，但洞察文案和下方曲线还是上一个地点的数据** —— 局部更新了不等于这次渲染成功了。所以端到端测试必须断言"所有面板"。
5. **无头 Chrome 强制最小视口 500px 宽。** 所以"375px 截图"其实是 500px 的布局被裁掉了右边。要看真实窄视口，得用一个 375px 宽的 iframe 承载页面。
6. **`gh auth login` 在 github.com 直连不通时，报的是 `Post .../access_token: unexpected EOF`** —— 而同一时刻 `api.github.com` 却可能是通的。给它注入代理环境变量即可，不需要改任何 git/gh 配置。

## 已知限制

老实说清楚，免得你拿它去做不该它管的事：

- **不处理夏令时。** 每个地点用的是固定的 UTC 偏移，D‑ST 切换期前后会有一小时误差。
- **闰年会偏一天。** 内部的天序表按非闰年（2 月 28 天）写的，跨 2 月 29 日的年份需要修正。
- **不含观测者海拔。** 只按海平面计算，高海拔地点会有分钟量级偏差。
- **不含地形和遮挡。** 不知道你对面有楼、有山。
- **方位角是真北，不是磁北。** 别直接拿去对指南针。
- **只有太阳。** 没有月亮、行星、恒星、银河。
- **视图是等距方位投影**（天顶居中、半径正比于天顶角），不是从某个位置看出去的透视效果。

## 可能有趣的下一步

按"做出来会不会让人想玩一下"排序：

1. **日行迹（Analemma）** —— 固定每天的同一钟点，把太阳位置点满一年，会得到那个著名的 8 字形。它同时编码了均时差和赤纬变化，是这张天球图最自然的延伸。
2. **日晷 / 影子模拟** —— 立一根杆子，按真实太阳方位画出一天和一整年的影子轨迹。直观到不需要解释。
3. **太阳高度角热力图** —— 横轴一年、纵轴一天，用颜色表示"此刻太阳有多高"。一屏看完一个纬度的全年光景。
4. **分享链接** —— 把地点 / 日期 / 时刻编码进 URL（`?lat=&lon=&date=`），任何场景都能一键发人。
5. **导出图片** —— 把当前视图导成 PNG/SVG，方便贴进文章或做视频素材。
6. **选址对比** —— 同一时刻并排两个地点，看太阳各自在哪；或者换成年光照比较。
7. **修掉已知限制** —— 闰年、夏令时、海拔。
